# 采源验收范式（多类型 · 多视频 · 长任务）

## 一、为什么不是"一套标准打天下"

不同类型视频的"好"不一样：教程要**能照着跑**，综述要**覆盖全**，面试题要**分层可背**，评测要**口径一致**。
所以标准拆成两层：

1. **机器判据（rubric.yaml）**：可自动计算的结构指标 + 每类视频的判定项清单；
2. **判定协议（本 skill）**：怎么抽样、怎么打分、多批怎么门禁、什么时候停。

> 结论：**标准写成 skill 合理，但不能只有 skill**。判据要落成数据文件（版本化、可被 CLI 读取），skill 只负责"何时用、怎么判、怎么控节奏"。

## 二、类型判定与判据

类型判定见 `engine/harvest.py: classify_video`（关键词启发式，模型可纠正）。
判据文件：`~/.dsh/harvest/rubrics.yaml`（仓库 `engine/rubrics.yaml`）。

| 类型 | 核心判据（判定项） |
|---|---|
| concept 概念讲解 | 定义准确、邻近概念区分、类比不误导 |
| tutorial 实战教程 | 前置条件、步骤可复现、坑与验证 |
| survey 论文综述 | 覆盖度、分类框架、争议与未解 |
| interview 面试/问答 | 答题分层、常见误区、可背诵框架 |
| review 工具评测 | 对比维度、成本与限制、替代方案 |
| opinion 观点解读 | 事实与观点分离、时效 |
| course 课程合集 | 大纲完整、单集独立性 |

通用自动项（每条都查）：转写 ≥800 字符、摘要五要素齐、抽帧 OCR ≥5 行、媒体 ≤80MB 且时长在窗口内。
通用判定项：事实准确（抽 5 点回对转写，错 ≤1）、忠于原意（不把推断写成结论）。

## 三、打分法

- 自动项：pass/fail，全过才算"结构合格"；
- 判定项：0–5 分；加权后 ≥4.0/5 为单条通过；
- 单条结论三态：**通过 / 有条件通过（缺非关键项）/ 不通过**；
- 批次结论：通过率 ≥80% 且无"不通过"集中同类问题。

## 四、多视频长任务协议（关键）

1. **分批**：每批 ≤10 条，按主题/类型混排，避免同源偏差；
2. **抽样审计**：每类型抽 ≥3 条或 20%（取大者）；自动项全量跑，判定项只抽；
3. **门禁**：上一批通过率 <80% 不进下一批，先修引擎/提示词；
4. **累计看板**：维护 `type × depth（快扫/深采/摘要）× pass` 矩阵；
5. **停止规则**：预算（条数/时长/磁盘）到顶，或连续两批边际新增可用条目 <10%；
6. **回填**：失败条目进重试队列（换模型/补抽帧/人工），不静默丢弃。

## 五、命令

```powershell
# 自动项自检（按库中状态）
python C:\Users\Administrator\.dsh\harvest\harvest.py audit --status summarized --limit 20

# 指定条目
python ...\harvest.py audit --ids bili:BV1b69gB5E3h bili:BV1GAwmzCEB4
```

输出：每条的类型、自动项 PASS/FAIL、待模型判定项清单、批次汇总。

## 六、验收报告模板

```
# 批次 N 验收报告
- 范围：类型/条数/采集时间
- 自动项：x/y 条全过
- 判定项：抽样 k 条，均分 x.x，问题 Top3
- 结论：通过 / 有条件通过 / 不通过（原因）
- 回填：待重试条目
- 下一批计划
```

## 七、反模式

- 只看条数不看类型适配（用教程标准评综述）；
- 抽样只抽高播放（幸存者偏差）；
- 自动项全绿就宣布验收通过（判定项没做）；
- 长任务不设门禁，问题积累到最后才发现。
